# 双手武器自动旋风斩监测模块

## 当前阶段

当前实现为 `0.6.3` 自动循环版本。按 `O` 后，插件在 `LC2.CreatureInputCtrl.UpdateInput(...)` 执行完成后使用 `SetInput(...)` 注入当前帧输入。启动时先长按 L，优先读取 `WeaponUI_THW` 三格蓄力条使用的隐藏阈值计数器：第二格满等于 `Hide_ChargeLevel1 + Hide_ChargeLevel2`，当前蓄力能量达到该累计值时同一帧立即松开。隐藏阈值不可用时再回退到 `THW_ChargeLevel`，最后回退到 `THW_Charge` 能量百分比。首次松开 L 的同一输入帧直接进入 J，并显式建立 `PressDown` 与 `Pressing` 缓冲，模拟玩家提前或稍晚报 J 时依赖的预输入。`HunterMotion.MotionActor.MotionComboReady(...)` 保留为诊断日志，不再决定首次 J 的触发时机。之后按 `J -> K -> L` 三个普通短按循环，不再每轮重新长按 L。

早期版本通过普通 `MonoBehaviour.Update` 或 Windows `SendInput` 注入。实机日志表明这种方式只能留下输入缓冲，动作仍停留在 `THW_Move_Accelerated`，并且残留的 K 缓冲会在移动或攻击时误触发翻滚。因此 `0.4.0` 移除了 `SendInput`，改为在角色消费输入之前完成内部状态注入，并在启动、停止时清理 J/K/L 的旧缓冲。

## 已确认的只读入口

| 类型或成员 | 用途 |
| --- | --- |
| `LC2.PlayerManager.LocalPlayer` | 定位本地玩家。 |
| `LC2.Player.OwnerHero` | 定位本地角色。 |
| `LC2.Hero.Weapon`、`LC2.WeaponRuntimeData.WeaponType` | 判断当前是否装备 `Two_Handed_Melee`。 |
| `LC2.Hero.RuntimeData.AtkSpd`、`BasicAtkSpd` | 记录当前攻速和基础攻速，用于后续动态窗口校准。 |
| `LC2.Hero.InputCtrl` | 读取 J/K/L 输入状态。 |
| `LC2.Player.mGameInputCtrl` | 实际注入 J/K/L 按键状态的主输入控制器。 |
| `LC2.CreatureInputCtrl.SetInput` | 写入 `PressDown`、`Pressing`、`Released` 等按键状态；每个 `KeyState` 都有独立输入缓冲。 |
| `LC2.CreatureInputCtrl.UpdateInput` | 每帧将物理输入复制到当前输入状态并处理缓冲；自动循环必须在该方法完成后、角色动作判定前注入。 |
| `LC2.CreatureInputCtrl.ClearKeyBuffer` | 清除指定按键及缓冲，避免 K 等旧状态残留并误触发翻滚。 |
| `LC2.Entity.PowerExecutor` | 读取角色能力执行器，用于查询双手武器蓄力计数器。 |
| `LC2.Power.PFAM_THW_Mod.CounterStr_THW_Charge` | 游戏官方蓄力能量计数器名。 |
| `LC2.Power.PFAM_THW_Mod.CounterStr_THW_ChargeLevel` | 游戏官方蓄力等级计数器名。 |
| `LC2.Power.PFAM_THW_Mod.HideCounterStr_THW_Hide_ChargeLevel1/2/3` | 游戏三格蓄力条使用的隐藏阈值计数器名；第二格满为前两个计数器当前值之和。 |
| `LC2.Power.PowerExecutor.Counter_GetCurValue` | 读取当前蓄力能量或蓄力等级。 |
| `LC2.Power.PowerExecutor.Counter_GetMaxValue` | 读取最大蓄力能量或最大蓄力等级。 |
| `LC2.WeaponUI_THW.ChargeLevel1/2/3` | UI 三格蓄力条的累计阈值；`ChargeLevel2` 是第二格刚满时对应能量。 |
| `LC2.CreatureInputCtrl.GetGameKeyState` | 读取 `PressDown`、`Pressing`、`Released`、`LongPressed` 等状态。 |
| `LC2.CreatureInputCtrl.GetGameKeyStateIncludeBuffer` | 读取输入缓冲窗口。 |
| `LC2.CreatureInputCtrl.GetGameKeyPressTime` | 读取当前按键持续时间。 |
| `LC2.Hero.MotionActor`、`LC2.MotionActor_LC2` | 记录当前动作名、动作类型、动作状态、帧、时间和播放速率。 |
| `HunterMotion.MotionActor.MotionComboReady` | 游戏动作事件判断下一段动作已经可接招时触发的公开通知方法；`0.6.3` 保留为诊断日志，不再作为首次 J 的触发依据。 |
| `CreatureEvent.THW_UseAtkCombo` 等双手武器事件 | 后续可在实机日志确认其触发顺序。 |

当前 `BepInEx/interop` 程序集中未找到此前讨论中提到的 `ChargeComponent`、`FSMWeaponInputs`、`ArenaPawn`、`FSMWeaponStyle` 这些公开类型。后续实现必须以当前游戏版本的 `LC2.MotionActor_LC2`、`CreatureInputCtrl` 和双手武器事件为准。

## 原型行为

1. 插件启动后默认只等待热键，不常驻刷日志。
2. 按 `O` 启动或停止自动循环；自动循环开启时同步记录监测日志。
3. 自动循环只有当前武器为 `Two_Handed_Melee` 且输入未锁定时才会启动。
4. 输入状态通过 Harmony 后置补丁注入到 `CreatureInputCtrl.UpdateInput` 之后，不再向操作系统发送真实键盘事件。
5. 自动循环阶段默认为：
   - 首次按住 L，默认等待 UI 第二格累计阈值 `Hide_ChargeLevel1 + Hide_ChargeLevel2`；当前能量达到该值的同一帧立即松开。
   - 若 UI 隐藏阈值不可用，回退等待 `THW_ChargeLevel` 达到 `TargetChargeLevel=2`；仍不可用时才回退等待能量百分比 `TargetChargeEnergyPercent=100`。
   - 若两类蓄力计数器都不可用，使用 `MeasuredChargeHoldSeconds` 或 `InitialChargeHoldSeconds` 兜底。
   - 首次松开 L 后在同一输入帧建立 J 的 `PressDown + Pressing` 缓冲并进入 `AttackTap`，不再额外等待连招 Ready。
   - `UseComboReadyDetection` 默认开启时只记录本地角色的 `MotionComboReady` 诊断事件；`ChargeReleaseWaitSeconds` 仅保留兼容旧配置文件，不再参与循环。
   - 点按 J `AttackTapHoldSeconds`。
   - 等待 `AttackToDodgeSeconds` 后点按 K `DodgeTapHoldSeconds`。
   - 等待 `DodgeToChargeSeconds` 后点按 L `ChargeTapHoldSeconds`。
   - 等待 `ChargeToAttackSeconds` 后回到 J，形成 `J -> K -> L` 循环。
6. 开启攻速自适应时，各阶段时间按 `BasicAtkSpd / AtkSpd` 缩放；装备横斩或纵斩 30% 攻速词条后会相应缩短阶段时长。
7. 达到目标蓄力等级或兜底能量后，插件会把实测按住时间写入 `MeasuredChargeHoldSeconds`，供计数器不可用时自动使用。
8. 启动、停止和异常退出都会清理 J/K/L 的输入缓冲，避免自动翻滚污染手动操作。
9. 监测日志记录：
   - 当前武器类型与攻速。
   - 当前蓄力能量、最大蓄力能量、UI 一/二/三格累计阈值和游戏提供的蓄力等级。
   - 当前动作名、类型、状态、帧、时间、动作速率、播放速率和时间倍率。
   - J、K、L 的按下、持续、松开、长按、输入缓冲和按压时间。
10. 状态变化时立即写日志；状态稳定时按 `SnapshotIntervalSeconds` 周期写日志。
11. 所有日志写入 BepInEx 控制台和日志文件。

## 输入时序依据

Cpp2IL 输出位于忽略目录：

- `Decompiled/_GameCpp2IL/DiffableCs/LC2.Core/LC2/CreatureInputCtrl.cs`
- `Decompiled/_GameISIL/IsilDump/LC2.Core/LC2/CreatureInputCtrl.txt`
- `Decompiled/_GameISIL/IsilDump/LC2.Core/LC2/KeyActionState.txt`

反编译证据说明：

- `UpdateInput` 会先把 `PlayerInputActions` 中真实设备的当前状态复制到 `_curFrameInputActionState`，再遍历并更新游戏输入缓冲。
- `SetInput` 会直接修改对应 `KeyActionState` 的单帧标志，并调用 `InputBuffers.UpdateInputKey(keyType, keyState)`。传入哪个 `KeyState`，就只更新哪个状态的缓冲。
- `SetInput(HardAttack, Pressing, 0)` 会同时设置 `WasPressed` 和 `Pressing`，适合长按的第一帧；它不会自动建立 `PressDown` 缓冲。持续阶段必须改用非零按压时间，否则每帧都会重新触发一次“刚按下”，导致蓄力反复重置。
- `0.6.3` 的首按注入同时调用 `SetInput(keyType, PressDown, 0)` 和 `SetInput(keyType, Pressing, 0)`。`GetGameKeyStateIncludeBuffer(..., PressDown)` 会先检查当前帧 `WasPressed`，再检查 `InputBuffers` 中的 `PressDown` 缓冲，因此可以覆盖动作逻辑早于或晚于注入执行的情况。
- `LateUpdateInput` 会清理单帧输入标志，因此 `SetInput` 后必须让角色逻辑在同一帧内读取状态。
- `ClearKeyBuffer(KeyType, true)` 会同时清理指定按键的缓冲和输入动作状态，适合在自动循环启停时清除 K 的残留。
- `InputBuffers.UpdateInputKey` 按 `KeyType + KeyState` 建立独立 helper；helper 的 `bufferTick` 为 `5`，`IsValid` 判断当前 Tick 与 StartTick 的差值不超过 5，约等于后续 5 个游戏帧的预输入窗口。

### 蓄力等级与时间依据

- `Decompiled/_GameCpp2IL/DiffableCs/LC2.Core/LC2/Power/PFAL_THW_Mod.cs` 中的 `UpdateChargeEnergy`、`CheckChargeLevel` 会更新 `CurChargeEnergy` 和 `CurChargeLevel`。
- `Decompiled/_GameCpp2IL/DiffableCs/LC2.Core/LC2/Power/PFAM_THW_Mod.cs` 公开了 `CounterStr_THW_Charge`、`CounterStr_THW_ChargeLevel`、`HideCounterStr_THW_Hide_ChargeLevel1/2/3`、`mChargeLevel1/2/3` 与蓄力速度参数。
- `Decompiled/_GameISIL/IsilDump/LC2.Core/LC2/WeaponUI_THW.txt` 中 `get_ChargeLevel1()` 读取 `Hide_ChargeLevel1`，`get_ChargeLevel2()` 在 `ChargeLevel1` 基础上累加 `Hide_ChargeLevel2`，`get_ChargeLevel3()` 继续累加第三格。`OnChargeValueChange()` 使用 `CurChargeEnergy > ChargeLevel2 + epsilon` 判断进入二阶段，因此第二格刚满时释放必须直接比较累计能量阈值。
- `BepInEx/interop/LC2.Core.dll` 中 `PowerExecutor.Counter_GetCurValue`、`Counter_GetMaxValue` 可读取上述计数器。
- `THW_ChargeLevel` 的最大值字段在实机中返回 `1000000`，是无效哨兵；插件不依赖最大等级显示，只读取当前等级并与 `TargetChargeLevel` 比较，且它现在只作为 UI 隐藏阈值不可用时的回退。
- UI 隐藏阈值和蓄力等级计数器都不可用时，插件回退读取 `THW_Charge` 的 `当前/最大` 能量百分比，避免计数器差异导致无法释放。
- 插件不再把首次蓄力时间写死；默认读取实际等级或能量并记录达到目标所需时间。
- `0.5.1` 修复首次长按期间每帧重复发送 `Pressing, 0` 的问题，并让计数器暂不可用时持续按住到 `MaximumAutoChargeSeconds=4`，不再被普通阶段的 1.5 秒缩放上限提前截断。
- `0.6.0` 移除“必须先确认重新起蓄”的延迟判定；首次蓄力在维护按键的同一帧检查并释放。循环 `ChargeTap` 改为与 J/K 相同的普通短按状态机，`ChargeTapHoldSeconds` 恢复为实际生效的 L 短按保持时间。
- `0.6.1` 改为优先使用 `WeaponUI_THW` 同源的隐藏蓄力格阈值。默认目标第二格满为 `Hide_ChargeLevel1 + Hide_ChargeLevel2`，不再依赖可能晚于 UI 前两格的 `THW_ChargeLevel`，修复第二格满后仍等待很久才释放的问题。

### 连招 Ready 依据

- `Decompiled/_GameCpp2IL/DiffableCs/Hunter.Motion/HunterMotion/MotionActor.cs` 公开 `MotionComboStart`、`MotionComboReady`、`MotionComboBaned` 以及对应事件；`MotionComboReady(BaseMotionData nextMotion)` 是“下一段动作已经可接”的通知点。
- `Decompiled/_GameCpp2IL/DiffableCs/LC2.Core/LC2/MotionEvent_ChangeMotion.cs` 中 `EventStart()` 调用 `MotionComboStart(...)`，`EventUpdate_Logic(int)` 在满足连招窗口条件后调用 `MotionComboReady(...)`，`EventEnd()` 调用 `MotionComboBaned(...)`。
- `Decompiled/_GameISIL/IsilDump/LC2.Core/LC2/MotionEvent_ChangeMotion.txt` 显示 `EventUpdate_Logic` 通过 `_sendComboEventStartToAI` 和 `_sendComboEventReadyToAI` 两个标志保证 Start/Ready 各触发一次；Ready 触发后会设置 `_sendComboEventReadyToAI=1`。
- `Decompiled/_GameISIL/IsilDump/Hunter.Motion/HunterMotion/MotionActor.txt` 显示 `MotionComboReady` 只转发 `nextMotion` 给公开事件，因此 Harmony 后置补丁可以安全监听该通知，不需要修改反编译源码或游戏程序集。
- `0.6.2` 曾据此新增 `MotionComboReadyPatch`，但实机日志确认蓄力释放动作没有向本地角色发出可用的 Ready 事件，始终走超时后才进入 J。
- `0.6.3` 改为在首次松开 L 的同一输入帧直接进入 `AttackTap`，并显式补建 `PressDown` 缓冲。`MotionComboReadyPatch` 保留为诊断日志，不再控制首次 J。

## 构建与部署

```powershell
dotnet build .\src\AutoWhirlwindMonitor\LC2AutoWhirlwindMonitor.csproj -c Release --no-restore
Copy-Item -LiteralPath .\src\AutoWhirlwindMonitor\bin\Release\LC2AutoWhirlwindMonitor.dll -Destination .\BepInEx\plugins\LC2AutoWhirlwindMonitor.dll -Force
```

## 下一步实测流程

1. 重启游戏，让新版插件加载。
2. 进入游戏并装备双手武器。
3. 按 `O` 启动自动循环。
4. 保存 BepInEx 日志中动作名称变化、输入状态和自动循环阶段；正常应看到 `InitialChargeHold -> AttackTap`，并输出“首次松开 L 后同帧预输入 J”，随后循环 `DodgeTap -> ChargeTap -> AttackTap`。
5. 对照“注入 J”日志中的动作名、动作时间、动作帧和输入冷却，确认 J 确实在松 L 后一帧以内建立缓冲，并观察下一次动作是否进入旋风斩。
6. 若首次释放后仍没有旋风斩，需要分别保存自动失败、手动早按成功、手动稍晚按成功三份日志，对比 `THW_UseAtkCombo`、动作名、动作时间和 J 输入帧。
